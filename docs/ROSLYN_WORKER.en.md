# Current Roslyn Worker Contract

> English translation; the [Chinese contract](ROSLYN_WORKER.zh-CN.md) is authoritative.

This document describes the first runnable `CL-WP-02` vertical slice. It does not claim that `CL-GATE-02` has passed.

The .NET 8 worker accepts local JSON over stdin or `--input`, binds original source bytes to a snapshot SHA-256 and transcoded text to a separate transport SHA-256, rejects unsafe paths, and uses Roslyn 5.9.0 syntax/compilation/semantic APIs. It emits deterministic graph nodes and provenance-bearing relations for declarations, direct calls, branches, throws, returns, state reads/writes, lifecycle scheduling, UnityEvent invocation, serialized references, and unknown `SendMessage` dispatch.

The Unity Context Builder now reads `.asmdef`, ProjectVersion, generated csproj defines, Compile globs, ProjectReference entries, and metadata HintPaths. It recursively builds an assembly dependency graph. The input assembler reads source bytes only through `SnapshotBinding`, checks both the snapshot and Unity context before and after assembly, and strictly supports UTF-8, BOM-qualified UTF encodings, and GB18030. Generated `Library/ScriptAssemblies` outputs remain `PROJECT_UNVERIFIED` without provenance. A revision-bound `EXTERNAL_UNITY_BUILD / ATTESTED_HASH_CLOSURE` may promote an exact local output to `PROJECT_ATTESTED`; the Worker independently validates its SHA-256. This is not a reproducible-build claim.

Export rejects an output older than any currently observed source or compile input. A successfully bound `PROJECT_ATTESTED` reference still keeps an explicit context limitation that the external build has not been independently reproduced.

The builder now evaluates asmdef include/exclude platforms, Define Constraints, and Version Defines. Version inputs are bound to `ProjectVersion.txt` and `Packages/packages-lock.json`; invalid or unparseable sources are explicitly downgraded. An excluded assembly cannot be assembled into worker input. The worker emits bounded relations for coroutine start/yield, async await, C# event/delegate subscription and publication, and common component lookup APIs. String coroutine targets remain `UNKNOWN`, and yield remains `STRUCTURAL`.

The Python `AnalyzerGraphDiffer` now combines OLD/NEW Worker results. It confirms stable type/method symbols, structurally pairs only unique synthetic signatures, accepts explicit reviewed hints for cross-symbol mappings, and emits added/removed/updated/moved/unchanged node and edge labels. Ambiguous candidates remain unmapped. The `graph-diff` CLI output is schema-validated and canonical-digest bound.

`analyze-change` performs the strict end-to-end path with either a revision-bound generated csproj or a revision-bound portable compile manifest. `export-compile-manifest` records base defines, exact source paths and semantic hashes, metadata names/hashes, and project references without absolute machine paths. A manifest is canonical-digest checked; stale source semantics fail closed. A live csproj may only locate a same-name, same-hash DLL and cannot contribute source or option semantics to a historical lane. Unity Context records whether its materialized project came directly from csproj or from a manifest, plus both origin and manifest digests.

An ET6 Unity 2020.3.26f1c1 read-only pilot assembled all 632 `Unity.Model` sources from a 9,352-file selected snapshot, including 24 worktree csproj files and 23 GB18030 legacy sources, and resolved a graph of 6 applicable assemblies, 12 dependencies, and 48 locked packages. Those assemblies contain no Version Define entries. Static analysis emitted 22,382 nodes and 18,874 edges, including 9,994 `READS_STATE`, 251 `WRITES_STATE`, 12 `AWAITS`, and 1,268 `DIRECT_CALL` edges. The result correctly remained `PARTIAL` with 51 diagnostics because generated project-assembly outputs lack bound provenance and symbols remain unresolved. A read-only manifest dry run produced 140 defines, 632 sources, 221 metadata references, and 5 project references without embedding the ET6 absolute path; its canonical digest is `c389dc3058fb284c5c6cf15b3e68a08cd90823e4eedb975455e29f3a9ce2d88d`. The normalized Git-status fingerprint remained 203 entries and SHA-256 `7c47c6fd1bce7f21375a4c965e6bcbb92ae937e765b84b30ea6af25432389228` before and after. `Unity.Model.csproj` and a compile-manifest baseline are both absent from HEAD, so HEAD-to-worktree analysis still correctly fails rather than retroactively inventing historical evidence.

Four of ET6's five ProjectReferences currently have ScriptAssemblies outputs and one is analyzer-only. Because ET6 has no committed compile-manifest baseline, `export-build-provenance --dry-run` correctly exits with code 2 instead of treating current DLLs as historical HEAD evidence.

The first human-annotated OLD/NEW Golden Change now runs through the real Worker in memory. Its frozen projection contains 19 OLD nodes, 25 NEW nodes, 11 mappings, 14 added nodes, 8 removed nodes, 14 added edges, 8 removed edges, and 8 unchanged edge pairs, with canonical digest `e3d40c21b0026a0e47f0ffc8d921d4350e3c4afcd3d9f98a44f71db575454155`. `CL-GATE-02` still requires 10–20 Golden Changes, historical-revision Unity context binding, verifiable ScriptAssemblies provenance, alias-aware state analysis, event removal, Inspector binding, performance evidence, and more adversarial cases.

See the [C#/Unity capability matrix](CAPABILITY_MATRIX.en.md) for exact coverage and limits.
